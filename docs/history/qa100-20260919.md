# История QA100: протокол из 12 условий (сентябрь 2026)

Архивная запись о завершённом прогоне. Команды и разрешения ниже относятся только к QA100 и не служат инструкцией для нового эксперимента. Текущая процедура находится в [runbook](../caniculus-runbook.md); перед любыми действиями на сервере действуют [правила ресурсов](../server-resource-rules.md).

**Статус на 19 сентября 2026 года: отдельный прогон 100 исходных ID запущен.** Пилот одного размеченного ID (`source_id=12265`) завершён ранее в каталоге `pilot-20260919-v2`. Владелец отдельно разрешил `smoke --count 100 --iterations 1`, предупредил коллег в RocketChat и подтвердил использование GPU 2. Чужая работа на GPU 2 не затрагивается. Перед любыми действиями прочитать [правила сервера](../server-resource-rules.md).

## Что именно будет запущено

Пилот выбирает 20 размеченных источников из обучающей части: 10 с меткой 0 и 10 с меткой 1. Для каждого исходного ID программа делает 12 вариантов исправления, всего не более 240 траекторий при одной итерации. После `replay` отдельный слепой пакет можно ограничить **100 уникальными исправлениями** для ручного аудита. Одинаковые исправления нескольких вариантов имеют один `request_id`, поэтому фактическое число уникальных заданий известно только после прогона. При менее чем 100 заданиях пакет содержит все доступные; объём пилота надо увеличить отдельным решением, сохранив новый каталог запуска.

Траектория каждой завершённой ветки и кэши записываются атомарно сразу. После каждого исходного ID обновляются `run_summary.json` и `cache_inventory.json`. При прерывании внутри ID повторный запуск с теми же входами и кодом пропускает готовые ветки. Зафиксированные входной CSV, код, конфигурацию, Gemini gateway revision, модель vLLM и число итераций **нельзя менять при возобновлении того же каталога**. Если изменилось что-либо из этого, нужен новый каталог запуска.

## Выбор среды и совместимость

На сервере наблюдаются Docker 29.8.0, драйвер NVIDIA 580.178.04 и выделенная пользователю GPU 2 — L40, UUID `GPU-7b7e27a5-a434-d736-eabd-b9414645af76`, 46 068 MiB. Уже загружен официальный образ [vLLM 0.23.0](https://github.com/vllm-project/vllm/releases/tag/v0.23.0) `vllm/vllm-openai:v0.23.0-cu129-ubuntu2404`, digest `sha256:370670abb329811c4c44c5712dbacc1d03a3b1be87c55fe3dfd62ea4a76f506b`. Он использует CUDA 12.9; [NVIDIA указывает](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html) совместимость с более новым драйвером R580. Загрузка модели, доступ контейнера только к GPU 2 и короткий ответ vLLM проверены от UID `a.maslov` с личными writable-кэшами.

На caniculus SSH настроен с `AuthorizedKeysFile none` и `AuthorizedKeysCommand /usr/bin/sss_ssh_authorizedkeys`: личный `~/.ssh/authorized_keys` игнорируется. Для временного доступа без изменения настроек сервера можно открыть с Mac один SSH ControlMaster по паролю и использовать его локальный сокет до закрытия сеанса. Постоянный ключ должен регистрироваться через предусмотренный администраторами механизм, а не изменением `sshd_config`.

Исправитель обслуживает `meta-llama/Llama-3.1-8B-Instruct` через vLLM по локальному HTTP. Обратная связь E/R/C/X вычисляется отдельно через Gemini gateway `openai/gemini-3.5-flash`. Эти модели работают в разных контейнерах/сервисах; vLLM не пытается исполнять Gemini. Структурированные ответы Gemini идут по `response_format` и проверяются по JSON Schema. Перед каждым живым запуском программа получает манифест gateway, закрепляет его хеш и проверяет `system_fingerprint` ответов. Полный конвейер KGGen/DSPy → Gemini → обратная связь → vLLM → `replay` проверен на одном размеченном ID; качество исправлений требует ручного аудита.

В локальном хранилище найден снимок S-BERT `all-MiniLM-L6-v2` ревизии `1110a243fdf4706b3f48f1d95db1a4f5529b4d41` (около 87 МБ); он перенесён в личный SSD и проверен внутри контейнера. Доступ к gated-репозиторию Meta проверен для коммита Llama `0e9e39f249a16976918f6564b8830bc894c89659`. Скачивать только корневые файлы `*.safetensors`, конфигурацию и токенизатор; `original/consolidated.00.pth` дублирует веса и не нужен vLLM. Токены не записывать в репозиторий, командную строку Docker или логи.

## Прогон 100 ID, начатый 19 сентября

Новый каталог — `/mnt/ssd/a.maslov/det_rep/work/runs/qa100-20260919/`; он не изменяет пилот `pilot-20260919-v2`. Команда `smoke --count 100 --iterations 1` использует прежние зафиксированные входной манифест `input_manifest-43a34fee6a4fadb2.json`, образ эксперимента `a-maslov-det-rep-experiment:pilot-20260919-v2`, конфигурацию, gateway и коммит Llama `0e9e39f249a16976918f6564b8830bc894c89659`. Выборка сбалансирована: 50 исходных CSV-меток 0 и 50 меток 1, всего до 1200 веток. Входные метки получены от GPT‑4o; это не человекоразмеченный gold RAGTruth.

Контейнер исправителя — `a-maslov-det-rep-vllm-qa100-20260919`, контейнер эксперимента — `a-maslov-det-rep-task-qa100-20260919`. Оба запущены без root от UID/GID `4200509:4200509`; GPU по UUID `GPU-7b7e27a5-a434-d736-eabd-b9414645af76` передана только vLLM. При контрольном осмотре до запуска на GPU 2 было 583 МиБ занято чужим процессом, который не останавливался. Больших загрузок в этой серии нет. Каждая ветка записывается атомарно, `run_summary.json` обновляется после каждого ID. Прямая экстраполяция первого ID (3:11) на 100 ID даёт около 5 ч 18 мин после загрузки модели; фактическую оценку нужно уточнять по прогрессу.

После успешного завершения всех 1200 веток личный фоновый скрипт `/mnt/ssd/a.maslov/det_rep/work/tools/finalize_qa100.sh` выполняет `replay` и `audit-export` **в Docker**, без сетевых вызовов и без root. Он выгружает все уникальные исправления в `/mnt/ssd/a.maslov/det_rep/work/audit-packets/qa100-20260919/requests.jsonl`. Затем отдельный контейнер запускает `scripts/export_variant_manifest.py` и создаёт закрытый `/mnt/ssd/a.maslov/det_rep/work/runs/qa100-20260919/variant_provenance.jsonl`: ровно одна строка на каждую ветку, с `arm`, списком блоков `E/R/C/X`, хешем промпта, `request_id`, текстом исправления и списком веток с тем же текстом. Например, `EC` и `ECX` сохраняются двумя строками с разными хешами промптов, даже если их `request_id` совпадает. Файл с разметкой веток остаётся внутри закрытого каталога запуска; независимому оценщику выдаётся только обезличенный `requests.jsonl`.

Скрипт финализации проверяет `completed=1200`, `failed=0`, затем `replay.missing=0` и число строк перед выпуском результата. При неполном прогоне он сохраняет артефакты и диагностический контейнер, освобождает **только собственную** GPU-память, а не создаёт ложный готовый пакет. Лог финализатора: `qa100-20260919/finalizer.log`. Отдельный монитор Codex проверяет прогресс каждые 15 минут и сообщает о сбое или завершении.

Владелец разрешил монитору восстанавливать этот же прогон после технических сбоев без изменения дизайна. При здоровом прогрессе монитор ничего не перезапускает. Одна неизменившаяся проверка считается наблюдением; после двух последовательных остановок прогресса или выхода собственного контейнера монитор изучает только закрытые артефакты и логи проекта. Для подтверждённых временных сбоев — таймаутов, HTTP 408/429/5xx, потери соединения или падения собственного vLLM — разрешено до трёх последовательных попыток продолжить тот же `qa100-20260919`; после 429 выдерживается как минимум один интервал монитора. Возобновление использует существующие атомарные checkpoint и те же закреплённые ресурсы. Если GPU 2 занята сверх ранее наблюдавшейся малой чужой нагрузки, целостность закреплённых ресурсов нарушена, заканчивается диск, причина неясна или требуется изменение параметров, монитор оставляет прогон остановленным и сообщает владельцу. Чужие ресурсы, серверные настройки и квоты не затрагиваются.

20 сентября прогон завершён после одного точечного возобновления. Первый проход сохранил 1199 веток и оставил `source_id=15583`, `arm=ERC` с `LocalLLMError`; диагностический файл не содержал текста исключения, поэтому точный механизм исходного сбоя неизвестен. После восстановления того же vLLM-контейнера из закреплённого digest и запуска существующего task-контейнера с неизменными командой, seed, входами, моделями и кэшами отсутствующая ветка успешно записалась, а failure-файл был удалён. Итог: 100 источников, 1200/1200 траекторий, 0 ошибок, `replay.missing=0`, 1200 строк в закрытом `variant_provenance.jsonl` и 714 уникальных запросов в слепом `requests.jsonl`. Все 1200 строк provenance ссылаются на существующие Gemini feedback-файлы с полем `claims`; найдено 100 различных feedback-снимков. Собственный vLLM-контейнер удалён, GPU 2 освобождена. Успешный повтор финализатора запускался с перенаправлением stdout, поэтому старый `finalizer.log` отражает только первый неполный проход; готовность подтверждена отдельной проверкой артефактов в непривилегированном Docker-контейнере.

## Подготовка разрешённого теста одного ID

Все операции на сервере выполнять от `a.maslov`, без `sudo`. Личная область — `/mnt/ssd/a.maslov`; `/mnt/data` на этом сервере отсутствует. Проверить владельца папки до записи и не менять права чужих каталогов. Для локальных передач с Mac использовать `rsync --bwlimit=5000` (КиБ/с, около 41 Мбит/с), без `--delete`. Копировать только файлы этого проекта и входные данные, а для снимка S-BERT применять `--copy-links`, поскольку его файлы в локальном кэше являются ссылками. Код, данные, веса, секреты, кэши и результаты должны остаться в личной папке на локальном SSD; не использовать домашний каталог или NFS для больших/временных данных.

Предлагаемая структура:

```text
/mnt/ssd/a.maslov/det_rep/
  repo/                 # точная копия кода для запуска
  inputs/               # source_info.jsonl и CSV, только чтение в контейнере
  models/sbert/         # локальный снимок S-BERT с разыменованными ссылками
  models/llama31/       # точная ревизия gated-весов Llama
  secrets/              # ключ gateway и, при загрузке весов, HF token; mode 0700/0600
  work/                 # split, манифест, кэши, runs, audit-packets
```

На сервере сначала создать свою область, остановившись, если путь принадлежит другому пользователю:

```bash
if [ ! -e /mnt/ssd/a.maslov ]; then (umask 077; mkdir /mnt/ssd/a.maslov); fi
test "$(stat -c %u /mnt/ssd/a.maslov)" = "$(id -u)" || exit 1
umask 077
mkdir -p /mnt/ssd/a.maslov/det_rep/{repo,inputs,models/sbert,models/llama31,secrets,work}
```

Затем с Mac передать точные локальные входы и код, не используя `--delete`. Для S-BERT обязательно разыменовать ссылки; скорость каждой передачи ограничена ниже дневного лимита:

```bash
cd /Users/maslovartemij/Projects/det_rep
rsync -a --bwlimit=5000 --exclude='__pycache__/' --exclude='*.pyc' \
  .dockerignore AGENTS.md Dockerfile.experiment README.md config.example.yaml pyproject.toml \
  det_rep docs gemini_gateway scripts tests \
  a.maslov@10.16.90.19:/mnt/ssd/a.maslov/det_rep/repo/
rsync -a --bwlimit=5000 \
  /Users/maslovartemij/Projects/hallu_smiles/data/source_info.jsonl \
  /Users/maslovartemij/Downloads/ragtruth_llama31_annotated.csv \
  a.maslov@10.16.90.19:/mnt/ssd/a.maslov/det_rep/inputs/
rsync -a --copy-links --bwlimit=5000 \
  /Users/maslovartemij/.cache/huggingface/hub/models--sentence-transformers--all-MiniLM-L6-v2/snapshots/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/ \
  a.maslov@10.16.90.19:/mnt/ssd/a.maslov/det_rep/models/sbert/
```

Ключ gateway записать вручную в `secrets/gateway-key` внутри каталога с правами 0700, сам файл сделать 0600; не вставлять ключ в историю shell, Docker `--env`, код или чат. Gated-веса Meta получить в собственный `models/llama31` ночью через официальный Hugging Face клиент, используя свой разрешённый HF token из отдельного файла 0600. Записать полный commit SHA снимка в `models/llama31-commit.txt`. При прерывании загрузки продолжить её в том же личном каталоге; не чистить общие кэши и Docker-образы других пользователей.

До запуска повторно проверить GPU, процессы, диск, владельца личной папки и доступность Docker командами только для чтения:

```bash
id -nG
docker version --format '{{.Server.Version}}'
nvidia-smi --query-gpu=index,uuid,name,memory.used,memory.total --format=csv,noheader
nvidia-smi --query-compute-apps=pid,gpu_uuid,used_gpu_memory --format=csv,noheader
df -hT /mnt/ssd
stat -c '%U %a %n' /mnt/ssd/a.maslov
```

Если GPU 2 занята, согласовать время в RocketChat. Никаких команд `kill`, `docker stop`, `docker rm`, `docker system prune` или удаления чужих файлов. Перед существенной нагрузкой заранее предупредить коллег в канале сервера.

Образ эксперимента строится из `Dockerfile.experiment`; научный Python при сборке и запуске работает от непривилегированного пользователя. vLLM запускается из зафиксированного официального образа также с `--user "$(id -u):$(id -g)"`. Для этого UID, которого нет в `/etc/passwd` образа, задаются `USER`, `LOGNAME` и отдельные writable-кэши в личном SSD. Названия обоих образов и контейнеров должны содержать `a-maslov`. GPU передаётся **только** контейнеру vLLM и только параметром `--gpus device=GPU-7b7e27a5-a434-d736-eabd-b9414645af76`; [Docker поддерживает выбор по UUID](https://docs.docker.com/engine/containers/gpu/). Экспериментальный контейнер GPU не получает. Локальный vLLM HTTP слушает `127.0.0.1`, а не общий интерфейс сервера.

Порядок теста одного ID:

1. Проверить правила, ресурс GPU 2, владельца рабочей области и доступ к gateway/весам; уведомить канал сервера. Записать точные версии образа, весов и входов.
2. Использовать уже загруженный образ vLLM и ночью получить gated-веса в личную область. Проверить, что снимок модели полон и ревизия известна. Собрать образ эксперимента из точной копии текущего кода.
3. Поднять **один** контейнер vLLM без root, с указанным UUID и умеренным `--gpu-memory-utilization` (начать с 0.55), `--max-model-len 8192`, локальным портом и личным дисковым кэшем. Проверить `/v1/models`, а затем один короткий ответ модели. Если модель не помещается или vLLM падает, остановиться и изучить **только свой** контейнер; чужую работу не трогать.
4. Запустить `prepare` в контейнере эксперимента с входами read-only и `work/` read-write. Записать путь и SHA-256 нового `input_manifest-*.json`.
5. Запустить `smoke --count 20 --iterations 1 --max-sources 1` в контейнере эксперимента без GPU. Указать один и тот же `--run-dir`, точный `--checkpoint` весов, `--embedding-path`, URL локального vLLM и gateway. Секрет gateway монтировать отдельным read-only файлом и передавать лишь путь через `HALLU_GATEWAY_API_KEY_FILE`. Проверить 12 траекторий или диагностические `failures/` и причину ошибок.
6. После первого ID выполнить `replay` (без моделей) и, если тест успешен, `audit-export --max-requests 100 --out-dir` в **отдельную** папку. Команде аудита передавать только `requests.jsonl`. `evaluation_assignment.json`, `run_identity.json`, кэши и логи оставлять закрытыми в рабочей папке. Продолжать остальные ID только по новой команде владельца.

Образцы интерфейса CLI находятся в [README](../../README.md). Полезные условия готовности: 20 обработанных ID, 240 завершённых траекторий, `failed=0`, `replay.missing=0` и до 100 строк в `requests.jsonl`. Если заданий менее 100, сообщить фактическое число; не подменять их дублями ради счётчика.

### Шаблон команд для разрешённого теста одного ID

Это справочный шаблон; фактические команды выполнялись по отдельным шагам с проверками. Для продолжения того же каталога после отдельной команды владельца использовать **ровно образ v2, тот же код, входы, конфигурацию и модели**, а в строке `smoke` убрать `--max-sources 1`. Перед повторным использованием проверить фактические `MODEL_COMMIT`, манифест, доступность GPU 2 и согласование нагрузки. Команды рассчитаны на shell `bash` пользователя `a.maslov` внутри SSH-сеанса. Они ничего не останавливают и не удаляют.

```bash
DET_REP_ROOT=/mnt/ssd/a.maslov/det_rep
MODEL_COMMIT='0e9e39f249a16976918f6564b8830bc894c89659'
MANIFEST_NAME='input_manifest-43a34fee6a4fadb2.json'
DET_REP_UID=$(id -u)
DET_REP_GID=$(id -g)

test "$DET_REP_UID" -ne 0
test "$(stat -c %u /mnt/ssd/a.maslov)" = "$DET_REP_UID"

test -f "$DET_REP_ROOT/models/llama31-commit.txt"

[[ "$MODEL_COMMIT" =~ ^[0-9a-f]{40}$ ]] || exit 1
test -f "$DET_REP_ROOT/models/sbert/config.json"
test -s "$DET_REP_ROOT/secrets/gateway-key"
test -f "$DET_REP_ROOT/inputs/source_info.jsonl"
test -f "$DET_REP_ROOT/inputs/ragtruth_llama31_annotated.csv"

cd "$DET_REP_ROOT/repo"
docker image inspect a-maslov-det-rep-experiment:pilot-20260919-v2 >/dev/null

docker run -d \
  --name a-maslov-det-rep-vllm-pilot-20260919 \
  --user "$DET_REP_UID:$DET_REP_GID" \
  --gpus device=GPU-7b7e27a5-a434-d736-eabd-b9414645af76 \
  --network host --read-only --tmpfs /tmp:rw,nosuid,size=8g --shm-size=8g \
  --mount "type=bind,src=$DET_REP_ROOT/models/llama31,dst=/model,readonly" \
  --mount "type=bind,src=$DET_REP_ROOT/work,dst=/work" \
  --env HOME=/work --env USER=a.maslov --env LOGNAME=a.maslov \
  --env HF_HOME=/work/hf-cache --env XDG_CACHE_HOME=/work/cache \
  --env UV_CACHE_DIR=/work/uv-cache --env TORCHINDUCTOR_CACHE_DIR=/work/torchinductor \

`curl` проверяет только реестр модели; до пилота нужен также короткий реальный ответ через `/v1/chat/completions`. Если контейнер не готов, изучить `docker logs a-maslov-det-rep-vllm-pilot-20260919` и статус своего контейнера. Не повторять `docker run` с тем же именем, пока предыдущий контейнер существует; разобраться с ним вручную после согласования.

```bash
DET_REP_CONTAINER=(
  docker run --rm --name a-maslov-det-rep-task-pilot-20260919
  --user "$DET_REP_UID:$DET_REP_GID"
  --network host --read-only --tmpfs /tmp:rw,nosuid,size=4g
  --mount "type=bind,src=$DET_REP_ROOT/inputs,dst=/inputs,readonly"
  --mount "type=bind,src=$DET_REP_ROOT/models/sbert,dst=/models/sbert,readonly"
  --mount "type=bind,src=$DET_REP_ROOT/work,dst=/work"
  --mount "type=bind,src=$DET_REP_ROOT/secrets/gateway-key,dst=/run/secrets/gateway-key,readonly"

[[ "$MANIFEST_NAME" =~ ^input_manifest-[0-9a-f]{16}\.json$ ]] || exit 1
test -f "$DET_REP_ROOT/work/$MANIFEST_NAME"

"${DET_REP_CONTAINER[@]}" smoke \
  --sources /inputs/source_info.jsonl \
  --answers /inputs/ragtruth_llama31_annotated.csv \
  --manifest "/work/$MANIFEST_NAME" \
  --work-dir /work --run-dir /work/runs/pilot-20260919-v2 \
  --embedding-path /models/sbert \

  --count 20 --iterations 1 --max-sources 1

```bash

После экспорта проверять число строк в `work/audit-packets/pilot-20260919-v2/requests.jsonl` и наличие приватной карты только в `work/runs/pilot-20260919-v2/`. В каталоге `work/` не делать общую очистку: кэши нужны для продолжения прерванного прогона.
