# Правила работы на вычислительных серверах Applied AI Center

Источник: [Правила использования вычислительных ресурсов](https://wiki.appliedai.tech/srv-rules), снимок страницы, предоставленный владельцем проекта 19 сентября 2026 года. Ниже сохранены правила из снимка; отдельный последний раздел содержит дополнительные инструкции владельца для caniculus. Если страница изменится, сверить этот файл с актуальной версией до следующего запуска.

## Правила центра

### Нагрузка на сеть (скачивание датасетов, больших файлов и т. д.)

- Использовать сеть для скачивания объёмных файлов днём разрешается на скорости до **50 Мбит/с**, ночью — без ограничений.
- Если необходимо превысить лимит, связаться с администраторами через [Infrastructure support](https://wiki.appliedai.tech/Helpdesk/Infrastructure_support).
- Процессы и контейнеры, использующие сеть вне лимитов и без согласования, будут остановлены, а учётная запись заблокирована.

### Предупреждение о нагрузке

- Если планируется занять значительную часть ресурсов сервера, заранее предупредить коллег в соответствующем канале сервера в RocketChat. Иначе контейнер может быть удалён без уведомления.

### Хранение данных

- Не хранить большие датасеты в `/home/user`. Для них предназначены отдельные директории, в большинстве случаев `/mnt/data`; детали уточнять у администраторов.
- Резервирование данных предоставляется по запросу. Данные, для которых не было заявки, не резервируются и могут быть утеряны.

### Вычисления в Docker

- Все вычисления проводятся в Docker. Запуск вычислений вне контейнера без предварительного одобрения администраторов может привести к отключению доступа без уведомления.
- Называть образы и контейнеры так, чтобы можно было определить владельца. Контейнеры без информации о пользователе в названии могут быть удалены без уведомления.
- Удалять ненужные версии **своих** образов после `build` и контейнеры, которыми больше не пользуетесь. Остановленные контейнеры старше двух недель могут быть удалены без оповещения.

### Использование GPU

- Без предварительного одобрения запрещено монтировать к контейнеру все GPU, в частности применять `--gpus all` или `--gpus {0-1}`. Такие контейнеры могут быть удалены без уведомления.
- Договариваться о резервировании ресурсов в чате сервера. После вычислений на общей GPU освобождать её память.

### Дисковое пространство

- Очистка Docker проводится раз в неделю: удаляются безымянные образы старше шести месяцев, build cache, остановленные и созданные контейнеры старше семи дней. На серверах действуют или будут действовать квоты. Для увеличения объёма обращаться в [Infrastructure support](https://wiki.appliedai.tech/Helpdesk/Infrastructure_support).

### Общедоступные сетевые папки

- На большинстве серверов есть общие хранилища; использовать каждое по его назначению. Не хранить в сетевых папках временные файлы, кэши и аналогичные данные.
- `/mnt/public-datasets` служит для передачи датасетов и наборов данных между серверами.
- `/mnt/sciml` служит для хранения данных проектов и их использования на разных серверах.

## Дополнительные ограничения владельца для caniculus

- Рабочая область проекта — **`/mnt/ssd/a.maslov`**. На caniculus нет `/mnt/data`; `/mnt/ssd` — локальный ext4, а `/mnt/public-datasets` — NFS. Входные данные, веса, кэши и результаты размещать в личной рабочей области, с закрытыми правами доступа. Кэши должны переживать остановку и удаление контейнера.
- Вычислительные процессы и контейнеры запускать **без root**. Не запускать Python-скрипты на хосте: научный код работает только в Docker.
- Владельцу разрешено использовать **GPU 2**, но это не даёт разрешения останавливать или удалять чужой процесс. Перед запуском снова проверить её загрузку и согласовать время использования в канале сервера. Монтировать только эту GPU по UUID, не диапазон устройств и не все GPU.
- Не удалять и не останавливать чужие файлы, процессы, образы или контейнеры. Очистка допустима только для явно идентифицированных собственных ресурсов.
- Владелец сначала разрешил пилот одного исходного ID, затем 19 сентября 2026 года отдельно разрешил запуск **100 исходных ID** на GPU 2. Коллеги были предупреждены в RocketChat о длительном прогоне. Чужой процесс на GPU 2 не останавливать и не удалять; очистку сервера не проводить. Дальнейшее расширение серии требует новой команды владельца.
- На время прогона 100 ID владелец разрешил автоматически диагностировать и устранять технические сбои, если это не меняет научный дизайн. Допустимо возобновлять только тот же каталог запуска с теми же входами, манифестом, кодом, образами, моделями, конфигурацией, seed, числом итераций и кэшами. Нельзя обходить квоты, менять серверные настройки или параметры эксперимента, переходить на другую GPU либо создавать заменяющий прогон. Для временных сбоев разрешён ограниченный повтор; при повторяющемся или неясном сбое работа останавливается с сохранением checkpoint.

Контрольные сведения из осмотра 19 сентября 2026 года: Docker 29.8.0; GPU 2 — NVIDIA L40 с UUID `GPU-7b7e27a5-a434-d736-eabd-b9414645af76` и 46 068 MiB памяти; NVIDIA driver 580.178.04. Эти показатели меняются и должны проверяться повторно непосредственно перед запуском.
